# CSV/Excel Cleaner

Консольная утилита на Python для очистки, конвертации, разделения и объединения
CSV/Excel файлов — типовая задача для выгрузок из 1С, интернет-магазинов и
CRM-систем, где данные обычно "грязные": разные форматы дат, дубли строк,
числа с пробелами и запятыми вместо точек, лишние пробелы в текстовых полях.

## Что умеет

**Очистка (`clean`)** — каждая операция включается отдельным флагом:
- удаление полных дублей строк (`--dedup`);
- удаление пустых строк и столбцов (`--drop-empty`);
- обрезка пробелов в текстовых полях (`--trim`);
- нормализация дат к единому формату `ДД.ММ.ГГГГ` (или
  `ДД.ММ.ГГГГ ЧЧ:ММ:СС`, если во входных данных было время) — распознаёт
  `05.03.2024`, `2024-03-06`, `07/03/2024`, `2024-03-06 10:15:00`
  (`--normalize-dates`). Невалидные даты вида `31.02.2024` не
  изменяются, но попадают в отчёт как некорректные;
- нормализация чисел — убирает пробелы-разделители, символы валют,
  определяет десятичный разделитель (если в числе и `,`, и `.` —
  десятичным считается тот, что правее) и приводит его к точке
  (`--normalize-numbers`). Числа не округляются — сохраняется исходная
  точность. Значения вида `1,234` (ровно 3 цифры после единственной
  запятой) неоднозначны — не изменяются и попадают в отчёт как
  "не распознано";
- `--all` включает все операции сразу.

Операции внутри `clean` выполняются в фиксированном порядке: обрезка
пробелов → удаление пустых строк/столбцов → нормализация дат →
нормализация чисел → удаление дублей. Дедупликация идёт последней,
поэтому дублями считаются и строки, различавшиеся только пробелами или
форматом даты/числа.

Столбцы для обработки дат и чисел определяются автоматически по образцу
значений, либо задаются вручную через `--date-columns` и `--number-columns`.

Перед записью результата в `.xlsx` или `.json` нормализованные числовые
столбцы приводятся к настоящему числовому типу (не тексту); для `.csv`
они остаются текстом с точкой как десятичным разделителем.

**Конвертация (`convert`)** — CSV/XLSX → CSV/XLSX/JSON, формат определяется
по расширению выходного файла.

**Разделение (`split`)** — один файл делится на несколько по значению
столбца (например, по категории или региону). Пустое значение столбца
превращается в файл `..._без_значения`; если два разных значения дают
одинаковое имя файла, второму добавляется суффикс `_2`, `_3` и т.д.

**Объединение (`merge`)** — несколько файлов с одинаковой структурой
столбцов объединяются в один.

Для CSV разделитель на входе определяется автоматически (`;`, `,` или
таб) по первым строкам файла; переопределить его можно через `--sep`,
разделитель на выходе — через `--out-sep` (по умолчанию `,`). Эти опции
доступны у `clean`, `convert`, `split` и `merge`.

После каждой операции в консоль выводится отчёт: сколько строк/столбцов
было и стало, сколько дублей удалено, сколько дат и чисел нормализовано —
чтобы результат работы был понятен и без открытия файла.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Примеры запуска

```bash
# Полная очистка CSV-файла
python clean_data.py clean sample_data/sales_january.csv -o clean.csv --all

# Только удаление дублей и обрезка пробелов
python clean_data.py clean data.csv -o clean.csv --dedup --trim

# Конвертация CSV в Excel
python clean_data.py convert clean.csv clean.xlsx

# Конвертация в JSON
python clean_data.py convert clean.csv clean.json

# Разделение файла по столбцу "Категория"
python clean_data.py split clean.csv --by Категория -o split_output

# Объединение нескольких файлов в один
python clean_data.py merge sales_january.csv sales_february.csv -o full_year.csv

# Файл с разделителем ";" на входе, "," на выходе
python clean_data.py clean data.csv -o clean.csv --all --sep ";" --out-sep ","
```

Полный список опций — `python clean_data.py <команда> --help`.

## Обработка ошибок

Скрипт не падает с трейсбеком — при проблеме выводит понятное сообщение
и завершает работу с кодом ошибки. Обрабатываются: отсутствующий файл,
неподдерживаемый формат, битая/неопределённая кодировка CSV, любые
ошибки чтения xlsx (повреждённый или не являющийся Excel-файл),
отсутствующий столбец, попытка объединить файлы с разной структурой.

## Ограничения

- Разделитель CSV на входе определяется автоматически по первым
  строкам файла — сравнивается количество `;`, `,` и таба, выбирается
  самый частый. На нестандартных или очень коротких файлах
  автоопределение может ошибиться — в этом случае задайте разделитель
  явно через `--sep`. Разделитель на выходе не зависит от входного и
  по умолчанию — запятая (`--out-sep` для изменения).
- Нормализация чисел рассчитана на распространённые российский
  (`1 200,50`) и европейский/американский (`1.234,56` / `1,234.56`)
  форматы. Если в числе только запятая и ровно 3 цифры после неё, а
  целая часть — не ноль (например, `1,234`), это неоднозначный случай:
  неизвестно, запятая здесь разделяет тысячи или десятичную часть.
  Такие значения не изменяются и попадают в отчёт как "некорректных
  чисел" — их стоит проверить и поправить вручную. Значения, вообще не
  похожие на число ни в одном формате, считаются отдельно — как
  "неподдерживаемый формат".
- Числа не округляются: если во входных данных было 3+ знака после
  запятой/точки, они сохраняются как есть.
- Невалидные даты, похожие по форме на дату, но не существующие
  (`31.02.2024`), не изменяются, но учитываются в отчёте отдельной
  строкой "некорректных дат".
- Автоопределение столбцов с числами (`detect_number_columns`)
  срабатывает только на "грязных" числах — с пробелами, запятой или
  символом валюты. Столбец с уже чистыми числами (`450`, `3200`) не
  считается "требующим нормализации" и не подставляется автоматически;
  если он всё же нужен для приведения к числовому типу в xlsx/json,
  укажите его явно через `--number-columns`.
- Excel (.xlsx) читается и записывается без сохранения формул и
  оформления: читается только первый (активный) лист, ячейки читаются
  и пишутся как значения, без учёта форматирования, стилей и формул
  других листов.
- Текстовые значения, начинающиеся с `=`, `+`, `-` или `@`, при записи
  в xlsx экранируются префиксом апострофа — иначе Excel может
  интерпретировать текст (например, комментарий или название товара)
  как формулу.
- При чтении CSV проверяется, что декодированный текст не похож на
  результат чтения в неверной кодировке (доля replacement-символов
  `�` и управляющих символов не выше порога). Если проверка не
  проходит ни для одной из поддерживаемых кодировок (UTF-8, CP1251),
  выводится понятная ошибка вместо испорченных данных.

## Тестовые данные

В `sample_data/` — три "грязных" примера для проверки:
- `sales_january.csv`, `sales_february.csv` — выгрузки продаж с дублями,
  разными форматами дат, "грязными" числами и пробелами (для `clean`,
  `convert`, `split`, `merge`);
- `orders_export.xlsx` — аналогичный пример в формате Excel, но с
  настоящими Excel-датами (в том числе с временем) и числовыми ячейками
  вместо текста — показывает, что `clean_data.py` корректно читает и
  нормализует не только "грязный" текст, но и типизированные ячейки
  Excel.
